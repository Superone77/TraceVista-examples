# Security and private data reports

If an example exposes a credential, personal information, or material that should not be
public, [report it privately](https://github.com/Superone77/TraceVista-examples/security/advisories/new).
Include the case filename, affected field or event ID, and a description of the issue.
Use redacted snippets; do not include a working API key or more private material.

For vulnerabilities in the viewer or conversion skill, use the
[TraceVista security policy](https://github.com/Superone77/TraceVista/blob/main/SECURITY.md).
It explains browser API key storage, model requests, chat history, and how to clear saved data.

Maintainers review the current `main` branch and coordinate removal or correction with the
reporter. If a credential is exposed, revoke it at its provider. Removing it from the latest
file does not remove it from earlier Git commits or existing downloads.

For ordinary example errors or improvements, use an issue with public, redacted evidence.
